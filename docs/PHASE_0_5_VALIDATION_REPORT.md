Дата: 2026-11-26. Статус: **Phase 0.5 выполнена в доступном объёме; физическая Windows 11 недоступна**.
Код приложения не писался; весь экспериментальный код — в `spikes/` (отдельный Cargo workspace, не связан ни с

## 1. Цель и границы

Цель — проверить архитектурные решения ARCHITECTURE_REVIEW.md на Windows и получить воспроизводимые факты до начала
реализации. Границы: прототипы и измерения; без реализации приложения; без перезаписи хранилищ; без публикации и
подписи; `aead-stream` не включается в основной граф зависимостей.

**Главное ограничение:** физический ПК с Windows 11 к сессии не подключён (проверено `list_computer_folders` —
список пуст). По решению владельца использован GitHub-hosted Windows CI. **Windows CI ≠ Windows 11**: это
Windows Server 2025 Datacenter (build 26100) в VM без интерактивного пользователя с PIN/биометрией и с отключённой
историей буфера обмена.

## 5. Методика и результаты

### W1. Argon2id — PARTIAL

**Методика.** `spikes/argon2-bench`: самопроверка по тестовому вектору RFC 9106 §5.3 (Argon2id; вектор сверен с
`rfc9106.txt`, строка 802); затем для каждого профиля — отдельный процесс (пик памяти на процесс), 1 прогрев + 5
замеров; min/median/max; пик рабочего набора (`GetProcessMemoryInfo.PeakWorkingSetSize` на Windows, `VmHWM` на Linux);
режим фоновой нагрузки (4 занятых потока); две сборки: без `parallel` (полосы считаются последовательно) и с
`parallel` (rayon); вариант с собственным затираемым буфером (`hash_password_into_with_memory`).

**Результаты [CI], медиана, мс:**

| Профиль (m, t, p) | Последовательно | С `parallel` | Посл. + 4 потока нагрузки | Пик памяти |
|---|---|---|---|---|
| 64 MiB, 3, 4 (RFC 9106 SECOND) | 104 | 43 | 170 | 68 MiB |
| 128 MiB, 3, 4 | 215 | 110 | — | 132 MiB |
| **256 MiB, 3, 4** | **444** | **194** | 668 | 260 MiB |
| 512 MiB, 3, 4 | 949 | 402 | — | 516 MiB |
| 1 GiB, 1, 4 | 703 | 317 | — | 1028 MiB |
| 256 MiB, 3, 4, свой затираемый буфер | 480 | — | — | 260 MiB |

Разброс min–max для 256/3/4 (послед.): 443–446 мс [CI], 574–606 мс [LNX]. Повторяемость в CI высокая (≤ 2 %), под
нагрузкой — до 774 мс (max). [LNX] значения: `spikes/results/linux-container/argon2-*.md`.

**Нехватка памяти.** [LNX] при `ulimit -v 200000` (≈195 MiB) профиль 256 MiB возвращает ошибку (`out of memory` /
`try_reserve_exact failed`) — без аварийного завершения. Исходник `argon2` 0.6.0: `Blocks::new` использует
`alloc_zeroed` и возвращает `Error::OutOfMemory` при null (`src/lib.rs:286-288`, `src/block.rs:168-181`); CHANGELOG
0.6.0: «Detect allocation failures in `hash_password_into`». **[CI] не проверено.**

**Находки.**
* **F-1:** `argon2` 0.6.0 освобождает внутреннюю память `Blocks` **без затирания** (`src/block.rs:190-200`, `Drop`
  вызывает только `dealloc`). Решение: в production — `hash_password_into_with_memory` с собственным буфером и
  `zeroize` после использования (измеренная цена: 480 vs 444 мс [CI]).
* `parallel` ускоряет ≈2.3× [CI], но добавляет 6 crates (по логу CI: rayon, rayon-core, crossbeam-utils, crossbeam-epoch, crossbeam-deque, either); CHANGELOG
  argon2: в 0.5.0 «Removed: Unsound `parallel` feature - see #380», в 0.6.0 «Added: `parallel` feature (#547)».
  Требует отдельного ревью до включения.

**Рекомендация (требует подтверждения на [WIN11]).** Профиль по умолчанию **256 MiB, t=3, p=4** сохраняется:
0.44 с [CI] без `parallel` — в целевом окне 0.5–1.5 с не попадает снизу, что **не** является проблемой безопасности.
Минимум 64/3/4 = RFC 9106 SECOND RECOMMENDED (параметры не отличаются от RFC). Калибровка на устройстве остаётся
обязательной.

### W2. Защита памяти Windows — PARTIAL

**Результаты [CI]:** минимальный рабочий набор по умолчанию 50 страниц (204 800 Б); `VirtualLock` 1 страницы — OK;
наибольшая успешная блокировка без настройки — 32 страницы, 64 страницы → `ERROR_WORKING_SET_QUOTA` (1453); после
`SetProcessWorkingSetSize` блокировка 4096 страниц (16 MiB) — OK; повторный `VirtualUnlock` → `ERROR_NOT_LOCKED` (158),
как в документации; `PAGE_NOACCESS` не блокируется (998); блокировка буфера `Vec` Rust (не выровнен по странице) —
OK; `CryptProtectMemory(SAME_PROCESS)` — шифрует/расшифровывает; длина не кратная 16 → ошибка 87.

**Выводы.** Для ключей (несколько страниц) достаточно лимита по умолчанию; результат `VirtualLock` необходимо
проверять и при ошибке продолжать работу с записью в журнал (кода ошибки, без данных). **`VirtualLock` не защищает от
чтения памяти процессом того же пользователя (см. W5, W9 — сканер именно так и читал память), от кейлоггеров,
гибернации и дампов** (документация гарантирует только непопадание в pagefile, пока страницы заблокированы).
Гибернация, crash dump — **NOT TESTED**.

### W3. Буфер обмена — FAIL (найдены дефекты), итог PARTIAL

**Результаты [CI]:**
* Формат `ExcludeClipboardContentFromMonitorProcessing` присутствует после `arboard ... exclude_from_monitoring()` — PASS.
* Очистка по таймеру — PASS; очистка не трогает чужое содержимое после записи другим процессом — PASS.
* **D-P1 (гонка).** Правило «очищать, если `GetClipboardSequenceNumber` не изменился с момента копирования» стёрло бы
  чужое содержимое **29/300** (run 3) и **39/300** (run 2) раз: `arboard` открывает и закрывает буфер сам, и между
  записью и чтением номера другой процесс успевает записать своё. Принятое правило: **сравнивать текущее содержимое с
  нашим значением под `OpenClipboard`** (документация: OpenClipboard «prevents other applications from modifying the
  clipboard content») — ошибочных очисток 0 из 300 при 47 корректных пропусках.
* **D-P2 (исключение не атомарно).** `arboard` 3.7.0 добавляет форматы исключения вторым шагом (`windows.rs:800-845`).
  Под конкуренцией `set()` вернул ошибку 6/300 (run 3), 2/300 (run 2), в run 1 — паника теста на `expect`. В run 3
  **1 раз секрет остался в буфере обмена без формата исключения**. Требование: любую ошибку копирования считать
  возможной утечкой и немедленно выполнять очистку по содержимому; рассмотреть собственную реализацию записи
  (CF_UNICODETEXT + формат исключения в одной сессии `OpenClipboard`) — **не прототипировано**.
* История/облачный буфер: `IsHistoryEnabled=false`, `GetHistoryItemsAsync` → `ClipboardHistoryDisabled` даже после
  `HKCU\Software\Microsoft\Clipboard\EnableClipboardHistory=1` → **NOT TESTED** (нужен [WIN11]).
* Секрет в буфере доступен любому процессу пользователя, пока он там — ожидаемо, задокументировано.

### W4. Windows Hello — NOT TESTED (только [DOC])

`KeyCredentialManager` создаёт ключи RSA 2048, приватный ключ в TPM (или программно без TPM), приложению недоступен;
сброс PIN удаляет ключи («key is lost»); поведение при удалении биометрии в изученных страницах не описано;
`UserConsentVerifier` — только да/нет, без ключа. В документации расхождение по паддингу подписи («PKCS #1 RSA PSS with
SHA256» vs «Pkcs1 for SignaturePadding»). Для получения ключа шифрования нужна детерминированная подпись; RSA-PSS со
случайной солью (RFC 8017) детерминированной не является. **Рекомендация:** отдельный этап на [WIN11] с TPM 2.0;
Windows Hello — только дополнительный способ при сохранённом Master Password; `UserConsentVerifier` для разблокировки
не использовать.

### W5. WebView2 — PARTIAL

**Методика [CI].** `spikes/tauri-shell`: Master Password (сгенерирован в JS во время выполнения, литерала в исходнике
нет) вводится в `<input type=password>` через `execCommand('insertText')`, читается один раз, поле очищается,
значение отправляется через IPC; секрет записи раскрывается в DOM на 300 мс и удаляется; затем Rust сканирует память
всех процессов `msedgewebview2.exe` до и после `location.reload()`; после выхода — сканирование файлов UDF.

**Результаты:**
* UDF = `%LOCALAPPDATA%\app.velfort.spike\EBWebView` (подтверждает исходник tauri 2.12.7
  `src/manager/webview.rs:559-569`); 163 файла; **сигнальные строки в файлах не найдены (0)** → SR-UI-5 для persistent
  storage — **PASS [CI]**. ACL UDF: SYSTEM, Administrators, пользователь.
* **Память:** renderer-процесс содержал Master Password: 2 вхождения UTF-16 + 4 UTF-8 до перезагрузки, **1 UTF-16 +
  4 UTF-8 после `location.reload()`**; ещё один процесс WebView2 — 4 UTF-8 до перезагрузки. Секрет записи (UTF-8) —
  3 до и 1 после. **Перезагрузка документа не удаляет пароль из памяти WebView2** (D-P3). Это подтверждает остаточный
  риск варианта A измерением.
* `general_autofill_enabled` в Tauri по умолчанию `true` (`tauri-utils` 2.10.4 `config.rs:2472`; wry вызывает
  `SetIsGeneralAutofillEnabled`) → **в production выставить `false`** (D-P4). Автосохранение паролей wry не меняет;
  значение WebView2 по умолчанию — `FALSE` [DOC, MS Learn ICoreWebView2Settings4].
* В UDF есть `Crashpad\reports` — отчёты о сбоях WebView2 могут содержать память процесса (**не проверено**, D-P10).
* Отключение автозаполнения **не** означает отсутствия данных в памяти процесса.

### W10. Backup prototype — PASS [CI, LNX]

`spikes/vault-crypto-proto` (22 теста, [CI] и [LNX]): `Connection::serialize` внутри read-транзакции → проверка
размера до второй аллокации → отдельная соль 16 Б и отдельный `backup_id` → Argon2id → HKDF
`"VELFORT/v1/backup-kek"` → случайный ключ бэкапа `BK` (обёрнут KEK_b) → **один вызов XChaCha20-Poly1305 in place** →
запись в **новый** файл (временный файл в целевом каталоге + `MoveFileExW(MOVEFILE_WRITE_THROUGH)` без замены).
Тесты: неверный пароль → `Auth`; бит-флипы во всех областях файла, усечение, удлинение, мусор → отказ; повреждённый
бэкап не создаёт цель; существующая цель → `TargetExists`; цель = источник → `TargetIsSource`; два бэкапа → разные
соли и id; бэкап требует текущий Master Password; сигнальные строки отсутствуют в хранилище, бэкапе, восстановленном
файле (UTF-8/UTF-16); после штатной работы журнала нет.

Память и время [CI] (тестовые параметры KDF): снимок 272 MB → создание 1094 мс, пик 526 MiB (≈1.9×); проверка +
восстановление 1071 мс, пик 786 MiB (≈2.9×). Аварийное завершение перед перемещением: цели нет, остался
`*.velfort-partial-*`, хэши исходников не изменились. Заполненный том: `Io(StorageFull)`, временный файл удалён.

**Лимит размера (обоснование, предложение).** Предел AEAD в `chacha20poly1305` 0.11.0 ≈ 256 GiB
(`src/cipher.rs:18,58`), он не ограничивает. Ограничивает память: ≈2× снимка при создании и ≈3× при восстановлении
(+ m Argon2id). Предложение: не фиксированное число, а проверка **перед** операцией: доступная память ≥ 3×S + m + запас;
жёсткий верхний предел 2 GiB снимка (запас против ошибок длины `u32` в обвязке; в прототипе длины `u64`). Оптимизация
восстановления (расшифровка в исходном буфере) уменьшит пик до ≈2× — **не реализовано**.

**Важно о гарантиях:** отдельная соль и отдельный ключ бэкапа **не защищают бэкап при компрометации Master Password**:
и хранилище, и бэкап открываются тем же паролем. Отдельный ключевой контекст защищает от другого: компрометации DEK
хранилища, повторного использования nonce/ключей между хранилищем и бэкапом.

### W11. Аудит aead-stream — PARTIAL

Исходник 0.6.0 (546 строк, `unsafe` нет, единственная зависимость `aead` 0.6), CHANGELOG — одна запись «0.6.0
(2026-06-28) Initial release»; по сравнению с `aead` 0.5.2 `src/stream.rs` — переименования трейтов/типов, алгоритм
тот же. 11 тестов [LNX, CI]: усечение, перестановка, повтор, порча любого бита, данные после последнего сегмента,
неверный AAD, прерванное шифрование, чтение last как next — всё отклоняется. Свойства, которые crate не даёт:
повтор (ключ, prefix) раскрывает XOR открытых текстов; после ошибки позиция не сдвигается — читатель обязан
останавливаться. **Независимый аудит не найден**: README и каталог упоминаний не содержат; отчёт NCC Group 2020
получить не удалось (страница перенаправляет, архив недоступен инструменту), поэтому его охват **не установлен**;
отсутствие ссылки в README само по себе не считается доказательством отсутствия аудита. **Рекомендация:** не
использовать в v1 (решение владельца подтверждено данными W10 — однократное AEAD покрывает измеренные размеры).

### W12. Файловая система — PARTIAL

[CI] ACL по умолчанию: `Documents\…\*.velfort`, `%APPDATA%`, `%LOCALAPPDATA%`, `%TEMP%` — SYSTEM, Administrators,
пользователь (F); `C:\Program Files` — Users (RX). Временные файлы: снимок бэкапа в памяти (временного файла нет);
восстановление — `*.velfort-partial-*` в целевом каталоге (содержит БД с полевым шифрованием), удаляется при сбое/запуске;
rollback journal — только во время транзакции.

Что может оставаться на диске [DOC + W8]: (1) удалённый файл rollback journal — SQLite **удаляет**, а не затирает его
(sqlite.org/tempfiles.html: DELETE mode «deleting the rollback journal file»), журнал содержит исходные страницы;
в VELFORT это только шифротексты; (2) старые версии страниц после `secure_delete`/`VACUUM` в свободных кластерах ФС;
(3) теневые копии тома, резервные копии ОС, синхронизация облака; (4) на SSD — перенесённые контроллером блоки (wear
leveling), недоступные ОС. **Гарантировать физическое уничтожение данных VELFORT не может**; все остатки — шифротексты
под DEK/BK (кроме папки данных WebView2, где секретов не найдено, W5).

## 7. Неустранённые риски

Вредоносное ПО с правами пользователя читает память и VELFORT, и WebView2 (это сделал сам сканер, W5/W9); пароль
варианта A в памяти WebView2 (D-P3); буфер обмена доступен всем процессам пользователя; история буфера не проверена;
полный откат файла хранилища не обнаруживается без внешнего состояния (CRYPTOGRAPHY §5.2 — ограничение остаётся);
физические остатки на SSD; отключение питания не проверено; argon2 `parallel` и `aead-stream` без найденного аудита;
поведение на физической Windows 11 — ни одна проверка.

## 8. Решения

**Без изменений:** Argon2id (мин. 64/3/4, по умолчанию 256/3/4 — до калибровки на [WIN11]); HKDF/KEK/DEK; XChaCha20-
Poly1305; AAD с `purpose` (D1 — исправление подтверждено тестом и мутационной проверкой: при одинаковом `purpose` тест
падает); `journal_mode=DELETE` + `synchronous=FULL` + `secure_delete=ON`; вариант A; восстановление только в новый файл;
бэкап с повторным вводом пароля, отдельной солью, без `aead-stream`; perMachine-установка; `downloadBootstrapper` +
отдельная offline-сборка.

**Требуют пересмотра/дополнения:** правило очистки буфера (D-P1/D-P2); `general_autofill_enabled=false`; отказ от
`withGlobalTauri`; собственный буфер Argon2id; NFC-зависимость; формат бэкапа в CRYPTOGRAPHY/DATA_MODEL (было STREAM,
стало однократное AEAD); оценка `parallel`.
