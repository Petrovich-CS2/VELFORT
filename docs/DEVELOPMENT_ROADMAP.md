## Этап 0.5. Проверка гипотез на Windows 11 (без функциональности)

Цель — подтвердить технические допущения на целевой ОС до массовой реализации. **Проверки в Linux-контейнере
не считаются подтверждением Windows-функций.** Результаты — в `docs/WINDOWS_VALIDATION.md` (будет создан по
факту измерений; без измерений документ не создаётся).

Подготовка (допускается минимальный код только для прототипов/бенчмарков, в отдельном каталоге `spikes/`,
не входящем в приложение — **требует отдельного разрешения владельца**):

1. Cargo workspace, `ui/`, CI (Linux для `velfort-core`, Windows-раннер для приложения), `cargo-deny`, ESLint.
2. Проверки W1–W13 (ARCHITECTURE_REVIEW §5):
   W1 Argon2id · W2 VirtualLock · W3 CryptProtectMemory · W4 буфер обмена и история `Win+V` · W5 события
   lock/sleep · W6 WebView2 UDF и PasswordAutosave · W7 capabilities/CSP/isolation и отсутствие сети ·
   W8 raw IPC · W9 прототип нативного поля пароля · W10 исследование Windows Hello (без реализации) ·
   W11 NSIS perMachine / MSI / webviewInstallMode / подпись тестовым сертификатом · W12 сбой при восстановлении ·
   W13 дамп процесса после блокировки.

**DoD:** по каждой W-проверке зафиксирован фактический результат (включая отрицательный) с конфигурацией
оборудования; профиль KDF по умолчанию утверждён; решение по варианту ввода Master Password (A в v1 / C в v1.x).

 отчёт по бенчмарку; решения по профилям KDF утверждены.

## Этап 1. Основное хранилище

* `crypto`: envelope, AAD с `purpose`, KDF, wrap/unwrap, HKDF-подключи различных типов — с тестовыми векторами и негативными тестами.
* `storage`: схема v1, транзакции, миграционный механизм (пустой).
* `auth`: создание, unlock, backoff, lock; `vault`: CRUD, корзина, папки, избранное, поиск по сводкам, манифест.
* 7 типов записей (Login, Secure Note, Credit Card, Identity, API Key, Wi-Fi, Software License).
* Автоблокировка (5 мин по умолчанию, без «Never»; таймер, сеанс Windows, сон).
* i18n: русский (основной), английский (дополнительный).
* UI: экран блокировки (фирменный), Sidebar, Search, Vault Items, Item Details, Quick Actions; тёмная/светлая темы.

**Тесты:** SR-TEST-1, 2, 3, 4, 9; unit для всех DTO. **DoD:** все SR-KDF, SR-ENC (кроме 6 rekey), SR-LOCK, SR-IPC, SR-UI выполнены.

## Этап 2. Генератор паролей

* Пароли (длина 8–128, классы, исключение неоднозначных `0 O o 1 l I |` — список утвердить), парольные фразы
  (словарь, разделитель, регистр, цифра), оценка энтропии и оценка силы пароля пользователя.
* Копирование без передачи в JS.

**Тесты:** SR-GEN-1…3.

## Этап 3. Работа с секретами

* Копирование логина/пароля/полей, автоочистка буфера, маскировка, временный просмотр с таймером, история изменений.

**Тесты:** SR-CLIP-*, SR-IPC-3/4, e2e T-11.

## Этап 4. Резервное копирование и смена ключей

* Бэкап (отдельная соль, `aead-stream`, снимок в памяти), проверка, восстановление в новый файл; смена Master Password; rekey с `VACUUM`; механизм миграций с фикстурами.

**Тесты:** SR-TEST-5, 6, 8; SR-BAK-*, SR-STO-*.

## Этап 5. Дополнительные функции (каждая — после отдельного мини-дизайна)

TOTP (RFC 6238) · несколько хранилищ · вложения · проверка слабых/повторяющихся/старых паролей (локально,
без сетевых сервисов вроде HIBP без согласования) · импорт/экспорт (форматы утвердить) · passkeys
(отдельное исследование: требования WebAuthn и API Windows для сторонних провайдеров — не изучались на этапе 0).

## Этап 6. Подготовка к релизу

* Иконка (`.ico` 16…256), установщик, подпись, метаданные `VELFORT`.
* Внутренний security-review по THREAT_MODEL; **рекомендован внешний аудит** до версии 1.0.
* Проверка товарного знака VELFORT.

## Критические риски и способы проверки

| # | Риск | Влияние | Способ проверки / снижения |
|---|---|---|---|
| R1 | Ошибка в использовании AEAD/AAD/nonce | Критическое | Минимальный API `crypto`, тестовые векторы, SR-TEST-2, ревью, внешний аудит |
| R2 | Секреты в JS-памяти WebView | Высокое | Архитектура «секрет не идёт в JS без reveal», e2e T-11; принять остаточный риск |
| R3 | Слабые параметры Argon2id на слабых ПК / медленная разблокировка | Высокое | Бенчмарк этапа 0.5, нижняя граница, калибровка |
| R4 | Потеря данных (порча, забытый пароль) | Критическое для пользователя | Транзакции, защитные копии перед миграцией/rekey, напоминания о внешнем бэкапе, явное предупреждение «восстановления нет» |
| R5 | Разработка в Linux-контейнере, цель — Windows | Среднее | Phase 0.5 (W1–W13) на Windows 11, Windows CI-раннер; Linux-результаты не переносятся на Windows |
| R9 | Master Password проходит через JS (v1) | Высокое | Меры SR-AUTH-1, прототип нативного ввода W9 |
| R10 | Неаудированные `aead-stream`, `argon2` | Среднее | Тесты, ревью исходников, внешний аудит до 1.0 |
| R6 | Цепочка поставки | Высокое | `cargo-deny`, `cargo-audit`, `npm audit`, lock-файлы, минимум зависимостей |
| R7 | Ошибки миграций формата | Высокое | Фикстуры каждой версии, защитная копия перед миграцией |
| R8 | Ложное чувство защищённости пользователя | Среднее | Честные тексты UI и документации об ограничениях |
