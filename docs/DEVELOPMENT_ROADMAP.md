## Этап 0.5. Каркас и проверка гипотез (без функциональности)

Цель — подтвердить технические допущения до массовой реализации.

1. Cargo workspace (`velfort-core`, `src-tauri`), `ui/` (Vite + React + TS), CI (Linux + Windows), `cargo-deny`, ESLint.
2. Минимальное окно Tauri с CSP, isolation, allow-list команд, одной capability — проверить на Windows 11, что
   ограничения действительно работают (негативный тест: вызов незарегистрированной команды отвергается).
3. **Бенчмарк Argon2id** на целевых Windows 11 ПК (минимум 2 конфигурации: современный и слабый ноутбук),
   таблица `m × t × p → время`; фиксация профилей по умолчанию в CRYPTOGRAPHY.md.
4. Проверка `arboard` с флагами исключения на Windows 11 (история `Win+V`).
5. Проверка `VirtualLock`/`CryptProtectMemory` через `windows-sys` в `security::memory`.

**DoD:** CI зелёный на обеих ОС; отчёт по бенчмарку; решения по профилям KDF утверждены.

## Этап 1. Основное хранилище

* `crypto`: envelope, AAD, KDF, wrap/unwrap, HKDF-подключи — с тестовыми векторами и негативными тестами.
* `storage`: схема v1, транзакции, миграционный механизм (пустой).
* `auth`: создание, unlock, backoff, lock; `vault`: CRUD, корзина, папки, избранное, поиск по сводкам, манифест.
* 7 типов записей (Login, Secure Note, Credit Card, Identity, API Key, Wi-Fi, Software License).
* Автоблокировка (таймер, сеанс Windows, сон).
* UI: экран блокировки (фирменный), Sidebar, Search, Vault Items, Item Details, Quick Actions; тёмная/светлая темы.

**Тесты:** SR-TEST-1, 2, 3, 4, 9; unit для всех DTO. **DoD:** все SR-KDF, SR-ENC (кроме 6 rekey), SR-LOCK, SR-IPC, SR-UI выполнены.

## Этап 2. Генератор паролей

* Пароли (длина 8–128, классы, исключение неоднозначных `0 O o 1 l I |` — список утвердить), парольные фразы
  (словарь, разделитель, регистр, цифра), оценка энтропии и оценка силы пароля пользователя.
* Копирование без передачи в JS.

**Тесты:** SR-GEN-1…3.

## Этап 3. Работа с секретами

* Копирование логина/пароля/полей, автоочистка буфера, маскировка, временный просмотр с таймером, история изменений.

**Тесты:** SR-CLIP-*, SR-IPC-3/4, e2e T-11.

## Этап 4. Резервное копирование и смена ключей

* Бэкап, проверка, восстановление; смена Master Password; rekey; механизм миграций с фикстурами.

**Тесты:** SR-TEST-5, 6, 8; SR-BAK-*, SR-STO-*.

## Этап 5. Дополнительные функции (каждая — после отдельного мини-дизайна)

TOTP (RFC 6238) · несколько хранилищ · вложения · проверка слабых/повторяющихся/старых паролей (локально,
без сетевых сервисов вроде HIBP без согласования) · импорт/экспорт (форматы утвердить) · passkeys
(отдельное исследование: требования WebAuthn и API Windows для сторонних провайдеров — не изучались на этапе 0).

## Этап 6. Подготовка к релизу

* Иконка (`.ico` 16…256), установщик, подпись, метаданные `VELFORT`.
* Внутренний security-review по THREAT_MODEL; **рекомендован внешний аудит** до версии 1.0.
* Проверка товарного знака VELFORT.

## Критические риски и способы проверки

| # | Риск | Влияние | Способ проверки / снижения |
|---|---|---|---|
| R1 | Ошибка в использовании AEAD/AAD/nonce | Критическое | Минимальный API `crypto`, тестовые векторы, SR-TEST-2, ревью, внешний аудит |
| R2 | Секреты в JS-памяти WebView | Высокое | Архитектура «секрет не идёт в JS без reveal», e2e T-11; принять остаточный риск |
| R3 | Слабые параметры Argon2id на слабых ПК / медленная разблокировка | Высокое | Бенчмарк этапа 0.5, нижняя граница, калибровка |
| R4 | Потеря данных (порча, забытый пароль) | Критическое для пользователя | Транзакции, автобэкапы, напоминания о внешнем бэкапе, явное предупреждение «восстановления нет» |
| R5 | Разработка в Linux-контейнере, цель — Windows | Среднее | Windows CI-раннер и ручные протоколы для SR-LOCK-3/4, SR-CLIP-1, SR-MEM-2 |
| R6 | Цепочка поставки | Высокое | `cargo-deny`, `cargo-audit`, `npm audit`, lock-файлы, минимум зависимостей |
| R7 | Ошибки миграций формата | Высокое | Фикстуры каждой версии, автобэкап перед миграцией |
| R8 | Ложное чувство защищённости пользователя | Среднее | Честные тексты UI и документации об ограничениях |

## Вопросы, требующие согласования

1. Утверждение стека Tauri 2 + Rust + React/TS и решения «шифрование полей вместо SQLCipher».
2. Второй фактор разблокировки (Secret Key / key file): нет / опционально / обязательно.
3. Windows Hello-разблокировка: не делать / этап 5 после анализа.
4. Бэкап: тот же Master Password или отдельный пароль бэкапа.
5. Целевое время разблокировки и профиль KDF по умолчанию (после бенчмарка).
6. Таймаут автоблокировки по умолчанию (предложено 5 мин) и разрешено ли «никогда».
7. Учитывать ли системное бездействие (`GetLastInputInfo`) или только активность в окне VELFORT.
8. Автообновление: нет (предложено) / подписанный опциональный updater.
9. Подпись кода Authenticode: есть ли сертификат.
10. Акцентный цвет Glacier Cyan `#5FB8CC` и концепция иконки «бастион сверху».
11. Язык интерфейса: русский, английский или оба с i18n с первого этапа.
12. `journal_mode`: WAL (производительность) или DELETE (один файл, проще копировать вручную).
13. Форматы импорта на этапе 5 (1Password `.1pux`, Bitwarden JSON, KeePass XML/KDBX, CSV).
