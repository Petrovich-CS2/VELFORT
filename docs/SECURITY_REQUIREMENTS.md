# VELFORT — Security Requirements

Статус: **ревизия 2 (после [ARCHITECTURE_REVIEW.md](ARCHITECTURE_REVIEW.md)), ожидает утверждения**. Каждое требование имеет идентификатор, формулировку
и способ проверки. Функция не считается завершённой, пока её требования не покрыты тестами (ТЗ §10.10).

Обозначения: **MUST** — обязательно для релиза; **SHOULD** — обязательно, если нет задокументированной причины;
**MAY** — опционально.

## 1. Выработка ключа (KDF)

| ID | Требование | Проверка |
|---|---|---|
| SR-KDF-1 | MUST: ключ из Master Password вырабатывается только Argon2id v0x13 | unit-тест, тестовые векторы RFC 9106 |
| SR-KDF-2 | MUST: соль 16 байт из CSPRNG ОС, новая при создании, при каждой смене пароля и для каждого бэкапа | unit-тест: две смены → разные соли; два бэкапа → разные соли |
| SR-KDF-3 | MUST: параметры не ниже `m=64 MiB, t=3, p=4`; ниже — отказ создавать и открывать | unit-тесты на границах |
| SR-KDF-4 | MUST: при чтении параметры ограничены сверху (`m ≤ 4 GiB, t ≤ 16, p ≤ 16`) | unit-тест на DoS-заголовок |
| SR-KDF-5 | MUST: Master Password не сохраняется на диск, в конфиг, в логи; нормализуется NFC | сканер сигнальных строк; тест NFC/NFD-эквивалентности |
| SR-KDF-6 | SHOULD: параметры калибруются на машине пользователя (цель 0.5–1.5 с) | бенчмарк-тест; протокол измерений на Windows 11 |

## 2. Шифрование

| ID | Требование | Проверка |
|---|---|---|
| SR-ENC-1 | MUST: все записи, папки, история, настройки хранилища, вложения, манифест — XChaCha20-Poly1305 | сканер открытых данных в БД |
| SR-ENC-2 | MUST: nonce 24 байта из CSPRNG для каждого шифрования; API не принимает nonce извне | ревью API; property-тест уникальности |
| SR-ENC-3 | MUST: каждый шифротекст имеет AAD с domain tag, format_version, vault_id, **purpose**, record_id, revision (CRYPTOGRAPHY §4.2) | негативные тесты перестановки, включая summary↔payload и history→payload |
| SR-ENC-9 | MUST: после расшифровки проверяется `summary.kind == payload.kind`; расхождение → запись повреждена | unit-тест |
| SR-ENC-10 | MUST: подключи — различные типы Rust; функция шифрования принимает только ключ своего класса | compile-fail тест (`trybuild`) или ревью |
| SR-ENC-11 | MUST: ошибка CSPRNG прерывает операцию; fallback-генераторов нет | тест с внедрённым отказом (`cfg(test)`) |
| SR-ENC-12 | MUST: rekey перешифровывает все классы объектов, выполняет `VACUUM`, проверяет расшифровку всех объектов новым ключом | интеграционный тест + сканер: старые шифротексты отсутствуют в файле |
| SR-ENC-4 | MUST: DEK 32 байта из CSPRNG; хранится только обёрнутым KEK с AAD = весь заголовок | тест изменения каждого поля заголовка |
| SR-ENC-5 | MUST: ошибка аутентификации никогда не возвращает частично расшифрованные данные | unit-тест |
| SR-ENC-6 | MUST: смена пароля переоборачивает DEK атомарно; rekey перешифровывает всё атомарно | тест с имитацией сбоя между шагами |
| SR-ENC-7 | MUST: манифест (с `header_hash`, историей, generation) обнаруживает удаление, добавление, откат отдельных записей, откат заголовка, подстановку старого манифеста | интеграционные тесты по таблице CRYPTOGRAPHY §5.1 |
| SR-ENC-13 | MUST: UI и документация явно сообщают, что полный откат файла не обнаруживается без внешнего состояния | ревью текстов |
| SR-ENC-8 | MUST: собственных криптоалгоритмов нет; только RustCrypto crates, утверждённые в CRYPTOGRAPHY.md | ревью `Cargo.toml`, `cargo-deny` |

## 3. Память и логи

| ID | Требование | Проверка |
|---|---|---|
| SR-MEM-1 | MUST: ключи и пароли — в типах с `Zeroize` on drop, без `Clone`, с `Debug` = `[REDACTED]` | unit-тест `format!("{:?}")`; ревью |
| SR-MEM-2 | SHOULD: страницы с DEK/подключами защищены `VirtualLock` (best effort, с логом кода ошибки) | Windows-тест |
| SR-MEM-3 | MUST: полные секреты расшифровываются на одну операцию и затираются после | ревью; тест дампа памяти (best effort) |
| SR-LOG-1 | MUST: в логи не попадают значения полей, заголовки, пароли, ключи, пути (по умолчанию) | тест: полный сценарий с сигнальными строками → grep логов |
| SR-LOG-2 | MUST: ошибки IPC содержат только код и ключ сообщения | unit-тесты маппинга ошибок |
| SR-LOG-3 | MUST: нет телеметрии, аналитики, crash-reporting, сетевых вызовов | `cargo tree` без HTTP-клиентов; e2e без сетевых запросов |
| SR-LOG-4 | MUST: release-сборка `panic = "abort"`, сообщения паники без данных | ревью `Cargo.toml` |

## 4. Блокировка

| ID | Требование | Проверка |
|---|---|---|
| SR-LOCK-1 | MUST: ручная блокировка удаляет DEK, подключи, сводки, индекс поиска | unit-тест: после lock любая команда → `VaultLocked` |
| SR-LOCK-2 | MUST: автоблокировка по бездействию (по умолчанию 5 мин) | тест с управляемыми часами |
| SR-LOCK-3 | MUST: блокировка при блокировке сеанса Windows | Windows e2e/ручной протокол |
| SR-LOCK-4 | MUST: блокировка перед сном/гибернацией | Windows ручной протокол |
| SR-LOCK-5 | MUST: frontend после блокировки не содержит данных записей | e2e (Playwright/WebDriver) |
| SR-LOCK-6 | MUST: блокировка очищает наше значение в буфере обмена | интеграционный тест |
| SR-LOCK-7 | MUST: таймаут по умолчанию 5 мин; допустимый диапазон 1–60 мин; режима «Never» в v1 нет | unit-тест валидации настроек |

## 5. IPC и frontend

| ID | Требование | Проверка |
|---|---|---|
| SR-IPC-1 | MUST: явный allow-list команд (`AppManifest::commands`) и одна capability для `main` | тест конфигурации (парсинг capabilities в CI) |
| SR-IPC-2 | MUST: DTO с `deny_unknown_fields`, лимитами длины и строгими типами | unit-тесты на некорректный ввод |
| SR-IPC-3 | MUST: секретные поля не входят в `items_list`/`item_get`; только `item_reveal_field` | unit-тест сериализации DTO |
| SR-IPC-4 | MUST: `item_copy_field` не возвращает значение | unit-тест |
| SR-UI-1 | MUST: CSP без внешних источников и без `unsafe-eval`; нет удалённого контента | тест конфигурации |
| SR-UI-2 | MUST: запрет `dangerouslySetInnerHTML`, `eval`, хранение данных записей в `localStorage`/`IndexedDB` | ESLint-правила в CI |
| SR-UI-3 | MUST: плагины `shell`, `fs`, `http`, `sql`, `updater` не подключены | тест `Cargo.toml`/capabilities |
| SR-UI-4 | MUST: devtools отключены в release | тест конфигурации |
| SR-UI-5 | MUST: данные записей не сохраняются в user data folder WebView2; автосохранение паролей/автозаполнение WebView2 отключены (механизм — W6) | сканер SR-TEST-1 по UDF |
| SR-AUTH-1 | MUST: поле Master Password — неуправляемое (`ref`), без React state/store/логов; `input.value` очищается сразу после отправки; документ перезагружается после unlock и lock | ESLint-правило + e2e |
| SR-AUTH-2 | MUST: документация и UI не утверждают, что Master Password изолирован от интерфейсного слоя (v1) | ревью текстов |
| SR-NET-1 | MUST: в MVP нет фоновых сетевых запросов; проверка обновлений в будущем — только по действию пользователя | мониторинг сети в e2e (W7) |

## 6. Буфер обмена

| ID | Требование | Проверка |
|---|---|---|
| SR-CLIP-1 | MUST: копирование секретов в Rust с флагами исключения из истории/облака Windows | Windows-тест |
| SR-CLIP-2 | MUST: автоочистка через N с (по умолчанию 30 с), только если содержимое наше | интеграционный тест |
| SR-CLIP-3 | MUST: UI не обещает гарантированного удаления из буфера | ревью текстов |

## 7. Хранение, бэкап, миграции, импорт

| ID | Требование | Проверка |
|---|---|---|
| SR-STO-1 | MUST: все изменения в транзакциях, `synchronous=FULL`, `secure_delete=ON` | тест прерывания |
| SR-STO-2 | MUST: неизвестная/новая версия формата → отказ без чтения данных | тест с фикстурой |
| SR-STO-3 | MUST: защитная копия файла перед миграцией и rekey (CRYPTOGRAPHY §7.5) | интеграционный тест |
| SR-STO-4 | SHOULD: `journal_mode = DELETE` (если владелец утвердит) | тест конфигурации |
| SR-DIST-1 | MUST: установщик ставит приложение per-machine (Program Files); NSIS `installMode: perMachine` или MSI | проверка прав на каталог установки (W11) |
| SR-DIST-2 | MUST: Authenticode-подпись до публичного релиза | проверка подписи в CI релиза |
| SR-BAK-1 | MUST: бэкап — отдельная соль + Argon2id от Master Password, случайный `BK`, `aead-stream` `StreamBE32` с XChaCha20-Poly1305; усечение, перестановка, дублирование, удаление последнего сегмента, данные после последнего сегмента, изменение заголовка обнаруживаются | негативные тесты |
| SR-BAK-2 | MUST: бэкап проверяется целиком в памяти (AEAD, integrity_check, заголовок, разблокировка, манифест) до записи на диск | интеграционный тест |
| SR-BAK-3 | MUST: снимок для бэкапа создаётся в памяти (`Connection::serialize`), временных файлов не создаётся | тест: мониторинг каталога и `%TEMP%` |
| SR-BAK-4 | MUST: восстановление — только в новый файл (temp в целевом каталоге → flush → `MoveFileExW` без замены); осиротевшие temp-файлы удаляются при запуске | интеграционный тест + W12 |
| SR-IMP-1 | MUST: импорт — в Rust, лимиты размеров/глубины/числа записей, предпросмотр | fuzz + фикстуры |
| SR-IMP-2 | MUST: экспорт в открытом виде — только после повторного ввода Master Password и предупреждения | e2e |

## 8. Генератор

| ID | Требование | Проверка |
|---|---|---|
| SR-GEN-1 | MUST: CSPRNG ОС; равномерный выбор (rejection sampling, без `% n` смещения) | статистический тест χ² на 10^6 символов |
| SR-GEN-2 | MUST: энтропия = `L · log2(N)` для пароля, `W · log2(|словарь|)` для фразы; указывается, если требования «минимум один символ класса» снижают её | unit-тесты расчёта |
| SR-GEN-3 | SHOULD: словарь парольных фраз встроен (EFF Large Wordlist, 7776 слов ⇒ log2(7776) ≈ 12.925 бит/слово); лицензию проверить перед включением | unit-тест размера/уникальности словаря |

## 9. Обязательные тесты (сквозные)

| ID | Тест |
|---|---|
| SR-TEST-1 | **Сканер открытых данных**: создать хранилище с сигнальными значениями (`VELFORT-CANARY-<uuid>` в каждом поле каждого типа) → проверить отсутствие сигнальных строк (UTF-8, UTF-16LE, base64, hex) в `.velfort`, `-wal`, `-shm`, бэкапе, логах, `%TEMP%`, конфиге |
| SR-TEST-2 | **Подмена**: flip каждого бита envelope (выборочно), перестановка blob'ов, перенос между хранилищами, откат ревизии, удаление строки, изменение каждого поля заголовка — всё обнаруживается |
| SR-TEST-3 | **Неверный пароль**: отказ, отсутствие расшифрованных данных, одинаковый ответ для пароля и подменённого заголовка |
| SR-TEST-4 | **Повреждённые файлы**: усечение, случайные байты, не-SQLite, SQLite без таблиц — без паники, с понятной ошибкой |
| SR-TEST-5 | **Смена пароля**: старый не работает, новый работает, записи не перешифрованы (те же шифротексты), сбой посередине безопасен |
| SR-TEST-6 | **Бэкап/восстановление**: roundtrip; восстановление в новое место; повреждённый бэкап отвергается полностью |
| SR-TEST-7 | **Импорт**: вредоносные фикстуры (огромные поля, глубокая вложенность, XSS, CSV-формулы, неверная кодировка) |
| SR-TEST-8 | **Миграции**: фикстуры каждой предыдущей версии → текущая версия, данные идентичны |
| SR-TEST-9 | **Блокировка**: SR-LOCK-1…7 |
| SR-TEST-10 | **Nonce**: property-тест уникальности (10^6 вызовов), отказ RNG, отсутствие API с внешним nonce |
| SR-TEST-11 | **Windows-проверки** W1–W13 (ARCHITECTURE_REVIEW §5): выполняются только на Windows 11; результаты Linux-CI не считаются их подтверждением |
